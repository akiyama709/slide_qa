# SlideQA

[English](README.md) | [日本語](README.ja.md)

発表前に自分のPDF・PPTX・資料JSONを開き，このMac内で索引化する質疑支援の試作版です．番号・表題・原文を示し，未検証（UNVERIFIED）の応答案を作ります．特定の個人の資料には固定していません．

現時点の完成版は，実マイクでの確認後に利用者が受け入れたv0.32.0です．草案は未検証で，生成を保留する場合もあります．以下の制約は引き続き適用されます．

通常の操作は「資料を開く」→本人が「開始」を一度押す→「停止」です．質問ごとの入力モード切替はありません．「開始画面に戻る」は現在のセッションを停止して資料を閉じます．通常画面に合成デモや動作確認のタブはなく，配布.appにもデモ資料を入れていません．

## 操作

1．資料を開き，ファイル名・枚数・本文・読込みの注意を確認します．
2．上部の「English（英語）」「日本語（Japanese）」で直接選びます．「設定」というメニューはありません．選択は次回起動にも保存します．未選択時はmacOSの優先言語から対応する最初の言語を使い，該当しなければ英語にします．切替で資料や質問のセッションを作り直しません．
3．「質問と応答案」で，本人が音声を使いたいときだけ「開始」を押します．この操作だけがマイク・音声認識の許可を求め，収音を開始します．「停止」で終了します．3問・3回の打切りはなく，一時障害から復帰して継続します．権限拒否や対応する機器がない場合は理由を示します．認識する質問と区切りの判定は日本語です．
4．「資料の参照」で根拠の原文を確認します．資料読込み中・読込み後は「開始画面に戻る」を使えます．資料の切替では旧セッションを取り消し，遅延した結果を採用しません．
5．補助の手入力は独立した「質問を入力…」ボタンにあります．マイクを開始せず，音声入力中は使えません．

表示言語はラベルとアプリが管理する状態・エラー文だけを切り替えます．資料・ファイル名・認識した質問・引用・草案は翻訳しません．英語表示で英語音声認識が加わるわけではありません．OSの許可ダイアログや未登録のサービス診断は，macOSの言語のままの場合があります．

AI草案と正確な原文引用を区別して表示します．複数の関連資料候補も，対応が未確定であると明示して試作版の草案へ渡せます．根拠がない場合は生成を保留します．出典があることやモデル照合の通過は，正しさの証明にはなりません．草案は原文と照合してください．口頭の訂正・取消・古い結果の破棄を保持しています．話者識別はないため，発表者の説明や疑問文を聴衆の質問と区別できない場合があります．

## 読み込む資料

| 形式 | 読み込む内容 | 制約 |
| --- | --- | --- |
| PDF | ファイル順の文字層 | 表題は先頭の非空行から推定します．発表ノートは取得しません． |
| PPTX | スライド順の本文・発表ノート | 表題プレースホルダーを優先します．非表示スライドも順序に含め，ノートのフッター・ページ番号を除きます． |
| JSON | 所定の資料索引 | 1からの連番と非空の表題が必要です．固定回答文・カスタム正規表現ルートは使いません． |

ファイルのバイト数・枚数・抽出文字数に固定のアプリ上限はありません．可能ならメモリマップで読み，ハッシュとZIP展開は小分けに処理し，解析・索引化の途中で取消とmacOSのメモリ不足通知を確認します．通知時は理由を示して停止します．利用可能な資源，フレームワーク，対応形式の制約はあるため，無制限のメモリや全資料の読込みを保証するものではありません．

PPTXをディスクへ展開しません．宣言された長さ・位置・展開完了・CRCを検査します．外部参照を取得せず，DOCTYPEと外部XML実体を拒否します．UTF-8のXMLと通常のZIPに対応します．破損・暗号化・ZIP64・保護された資料は読み込めない場合があります．旧PPT・PPTM・Keynoteには未対応です．

OCR，図表・画像・数式の意味理解，配置の再現は行いません．文字を取得できない画像のみの資料は拒否します．一部が空の資料ではページ順を保持し，注意を示します．推定表題，複雑な読順，印刷番号は元資料との確認が必要です．失敗時に旧資料で処理を続けることはありません．

## 要件とビルド

macOS 26以降，Swift 6.2以降，スクリプト用Python 3を使用します．生成には利用可能で日本語対応の端末内SystemLanguageModel，音声には既存の端末内日本語認識と本人の許可が必要です．モデルや音声資産の新規取得，APIキー，クラウドへの切替はありません．

```sh
swift test
python3 Scripts/build_app.py
open dist/SlideQAPrototype.app
```

通常のSwiftPMを使います．ビルドスクリプトは鍵を使わないアドホック署名を付け，既存出力を上書きしません．別の出力先は --output で指定します．起動・インストール・公証・OS設定変更はしません．バイナリは公開対象外です．

既存のSlideQAを終了してから，起動引数で資料を選ぶ方法もあります．

```sh
open dist/SlideQAPrototype.app --args --deck /absolute/path/presentation.pptx
```

PDF・JSONも使えます．資料はリポジトリ外に置いてください．

## JSON索引

最小の形式例です．

```json
{
  "sourceFile": "local-deck.json",
  "pageCount": 1,
  "slides": [
    {
      "page": 1,
      "title": "架空の装置の確認",
      "text": "装置の状態を確認します．",
      "notes": "形式を説明する架空の例です．"
    }
  ]
}
```

page・title・text・文字列のnotesが必要です．ページは1からの連番でpageCountと一致させ，表題を空にしません．JSONでは本文とノートを両方空にはできません．printedNumbersVerifiedやsourceSHA256などの入力を原本の検証済みという意味では信用しません．元ファイルと抽出索引のダイジェストは内容の識別子で，事実・印刷番号・見た目の正しさの証明ではありません．

## 開発者の試験

合成資料は試験と別のヘッドレスツールのために残し，通常アプリでは表示しません．次の開発用ツールは，モデル・マイク・GUIを使わずに原文を検索します．

```sh
swift run SlideQADemoCheck --deck /absolute/path/presentation.pptx --query "humidity"
```

表題だけの一致は，引用0件の根拠不足の場合があります．補助の独立ライター試験は，既存のpython-pptxとReportLabがある環境で実行できます．新しいソフトは導入しません．

```sh
python3 Scripts/create_import_fixture.py /tmp/slideqa-import-check/fictional.pptx
python3 Scripts/create_import_fixture.py /tmp/slideqa-import-check/fictional.pdf --format pdf
SLIDEQA_IMPORT_FIXTURES=/tmp/slideqa-import-check swift test
```

この独立ファイル試験はSLIDEQA_IMPORT_FIXTURESの指定時だけ有効です．通常の試験は小さな架空ファイルを生成します．

## 検証と公開対象

[検証記録](docs/verification.md)を参照してください．v0.32.0は連続質問の処理を維持し，合成検証で通常利用の診断記録を上書きする不備を修正しました．その後，利用者が通常アプリを実マイクで確認し，この版を受け入れました．認識・質問の検出・実際の回答生成が確認できました．一方で生成保留やモデルエラーもあり，全問に回答できたという結果ではありません．

通常試験の生成器と音声イベントは模擬です．別の署名済みデスクトップ検証では，実際の端末内モデルから合成5問への応答を得て，可視ウィンドウ内のSwiftUI回答欄の更新を確認しました．さらに，合成5種類を4巡する20件の実モデル連続試験を実施しました．生成中の取消2回と次問での復帰を含み，完了した20件すべてがモデル照合を通り，合成資料の内容・引用先と一致しました．開始は一度で，停止後の入力も拒否しました．これらの実モデル試験ではマイクや画面取得を使っていません．

同じ署名済みの最小モデル診断は，コーディングエージェントの実行サンドボックス内ではModelManagerServices.ModelManagerError / 1008で失敗し，個別に承認された制限外の実行では回答しました．起動サービス照会も制限内では失敗し，制限外では成功しました．この実行環境の差を，アプリの設定変更や制限解除処理として組み込んでいません．合成検証は通常利用の収音診断を上書きしません．

画素による見た目・キーボード・VoiceOver，長時間の実音声利用，多様な新資料に対する実モデル品質は未検証です．20件の実モデル試験の所要時間は，安定仮確定の待ち時間を含め1件あたり約2.40〜3.83秒で，3秒以内の応答を保証しません．誤った草案，生成保留，サービス・デコードのエラーが起こる場合があります．この版を受け入れたことは，それらの制約が解消したという意味ではありません．通常の音声はメモリ内で処理し，録音ファイルを保存しません．外部モデルAPIや資料のアップロード経路はありません．

公開対象はソース・試験・説明・架空の試験資料です．実資料・ノート・録音・私的なプロンプトや回答・ログ・秘密情報・モデル・ビルド出力はリポジトリと履歴に含めません．

```sh
python3 Scripts/check_publication.py --tracked
python3 Scripts/check_localization.py
```

CIはソース境界・合成資料・言語リソース・英語説明書・Python構文を検査します．Appleフレームワーク，実モデル・音声・GUIは検証しません．ライセンスは所有者の判断事項として未設定です．
