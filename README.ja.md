# SlideQA Prototype

[English](README.md) | [日本語](README.ja.md)

発表前に「資料を開く…」から，任意のPDF・PPTX・資料JSONを選び，このMac内で索引化する質疑支援の試作版です．特定の個人の発表資料には固定していません．通常起動では資料未選択の画面になり，収音・生成は始まりません．架空6枚の合成デモは，明示して選んだ場合だけ使用します．

本人が「開始」を一度押すと，日本語の質問を継続して処理し，「停止」で終了します．質問ごとの入力モード切替はありません．資料の選択は発表前に行い，収音中や動作確認中は切替を無効にします．UIと音声処理は日本語です．

AIの文章は未検証（UNVERIFIED）の草案です．原文引用と新しい文章を区別し，番号・抽出表題・原文を表示します．引用の存在や同じモデルの照合は，正確性の証明にはなりません．使用前に内容を確認してください．口頭の訂正・取消と古い結果の破棄を保持しています．

## 対応する資料

| 形式 | 読み込む内容 | 制約 |
| --- | --- | --- |
| PDF | ファイル内の順序に沿った文字層 | 表題は文字の先頭行から推定します．発表ノートは取得できません． |
| PPTX | スライド順序に沿った本文・発表ノート | 表題プレースホルダーを優先し，なければ先頭の文字から推定します．非表示スライドも順序に含め，ノートのページ番号・フッターを除外します． |
| JSON | 所定の形式のローカル索引 | 固定回答文やカスタム正規表現ルートは取り込みません． |

画像のみのPDFのOCR，図表・画像・数式の意味理解，元の配置の再現は行いません．抽出可能な文字が全くない資料は，明示して読込みを拒否します．一部のページだけ文字がない場合は順序を保持し，注意点を表示します．番号はファイル内の順序であり，印刷番号は検証しません．抽出表題も原本と合わせて確認してください．

PDF/PPTXは100 MiB，1〜500枚までです．本文とノートは各欄20,000文字，全文合計2,000,000文字までです．PPTXのXMLはUTF-8に対応し，1部分4 MiB，読込み合計32 MiBまでに制限します．破損・暗号化・ZIP64・パスワード又はコピー制限がある資料などは読み込めない場合があります．旧PPT・PPTM・Keynoteには未対応です．

PPTXはメモリ内で読み，アーカイブの中身をディスクへ展開しません．外部参照を取得せず，XMLの外部実体やDOCTYPEを拒否します．

別の資料を選ぶと，旧セッションを停止し，質問・応答案・索引を消去します．前のファイルの遅延した読込み結果は採用しません．失敗時に旧資料で処理を続けることもありません．

## 要件・ビルド

macOS 26以降，Swift 6.2以降，スクリプト用のPython 3を想定しています．生成には利用可能で日本語対応の端末内SystemLanguageModel，音声には既存の端末内日本語認識と本人によるマイク・音声認識の許可が必要です．モデルや音声資産の取得，APIキーの要求，クラウドへの切替は行いません．

```sh
swift test
swift run SlideQADemoCheck
python3 Scripts/build_app.py
open dist/SlideQAPrototype.app
```

通常のSwiftPMを使用し，隔離を無効にするフラグは保存していません．build_app.pyは合成デモと実行ファイルをまとめ，鍵を使わないアドホック署名を付けます．既存の出力先を上書きしないため，別の出力先は --output で指定します．起動・インストール・公証・OS設定変更は行いません．アプリのバイナリは公開対象外です．

## 操作

「資料を開く…」でファイルを選び，ファイル名・枚数・抽出本文・注意点を確認します．「質問と応答案」で本人が「開始」を押した場合だけ収音を開始し，必要なOSの許可も本人が判断します．「停止」で終了します．「資料の参照」では音声なしで検索でき，手入力と診断は補助の「動作確認」にあります．

話者識別はありません．発表者自身の説明や疑問文を聴衆の質問と区別できない場合があります．

起動時に指定する方法もあります．既存のインスタンスを終了してから使用します．

```sh
open dist/SlideQAPrototype.app --args --deck /absolute/path/presentation.pptx
```

同じ指定でPDF・JSONも使用できます．資料はリポジトリの外に保存してください．

## JSON形式

JSONは5 MiBまでです．各スライドに page・title・text・文字列のnotesが必要です．

```json
{
  "sourceFile": "local-deck.json",
  "pageCount": 1,
  "slides": [
    {
      "page": 1,
      "title": "架空の装置の確認",
      "text": "装置の状態を確認します．",
      "notes": "形式説明用の架空例です．"
    }
  ]
}
```

ページは1から始まる重複のない連番で，pageCountと一致させます．表題は300文字以内で空にできません．JSONの本文とノートを両方空にはできません．枚数・文字数の上限は前述のとおりです．入力のprintedNumbersVerifiedやsourceSHA256を元資料の検証済みという意味で信用しません．「動作確認」では元ファイルと抽出索引のハッシュを区別して表示します．いずれも内容の識別用で，正確性・印刷番号・見た目の証明にはなりません．

## 録音なしの確認

「動作確認」の準備状態ボタンは，利用可能性と既存の認可状態を読みます．許可申請・録音・生成・ダウンロードは行いません．別のデモ確認ボタンは，架空6枚について3問を端末内モデルで処理します．選択中の実資料，音声，画面描画，話者識別の検証ではありません．外部 --deck 指定時にはデモ確認を無効にします．

```sh
open dist/SlideQAPrototype.app --args --verify-local-answers-no-audio --disable-microphone
```

この明示した診断起動は最大4分で中止・保存・終了します．結果はユーザーのApplication Support内のSlideQA/Diagnosticsに保存し，リポジトリには書きません．

実際の資料ローダーと原文検索を，GUI・モデル・マイクなしで確認する方法もあります．

```sh
swift run SlideQADemoCheck --deck /absolute/path/presentation.pptx --query "スライド1の内容を教えてください．"
```

出力JSONは，ページの候補と根拠本文の有無を区別します．表題だけの一致ではinsufficientとなり，引用が0件の場合があります．

補助のScripts/create_import_fixture.pyは，既存のpython-pptxでPPTX，ReportLabでPDFを作成します．リポジトリ外へ架空資料だけを書き，新しいソフトは導入しません．使用するPython環境に両方が既にある場合は，次の手順で独立ライターの実ファイル試験を有効にできます．

```sh
python3 Scripts/create_import_fixture.py /tmp/slideqa-import-check/fictional.pptx
python3 Scripts/create_import_fixture.py /tmp/slideqa-import-check/fictional.pdf --format pdf
SLIDEQA_IMPORT_FIXTURES=/tmp/slideqa-import-check swift test
```

独立ファイルの統合試験はSLIDEQA_IMPORT_FIXTURESを指定した場合だけ実行します．通常の試験は，これらのPythonパッケージなしで小さなパーサー用資料を作成します．

## 検証範囲と公開対象

検証の詳細は[検証記録](docs/verification.md)に記載します．v0.24.0はローカルでビルドし，独立したソフトが書いた架空PDF/PPTXを実際のローダーで読む試験を含め，8スイート67試験が通過しました．コンパイル，模擬セッション，実ファイルの読込み，実モデル，実音声，GUIを区別します．この版のファイル選択の実操作，新しい資料に対する実モデルの品質，実音声，GUI・アクセシビリティの実操作は未検証です．3秒以内の応答は達成・保証しておらず，回答の品質や保留率は端末内モデルに依存します．

通常の音声はメモリ内で処理し，音声ファイルを保存しません．資料・音声を外部モデルAPIへ送る経路はありません．ただし，端末内モデルの誤答や意図しない命令追従を完全には防げません．

公開対象はソース・試験・説明・新しく作成した架空のデモです．実資料・ノート・録音・私的なプロンプトや回答・ログ・鍵・モデル・ビルド成果物は，リポジトリと履歴に含めません．追加内容を検査してください．

```sh
python3 Scripts/check_publication.py --tracked
```

CIは公開内容・合成資料・Python構文の検査です．Appleフレームワークのビルド，モデル・音声・GUIは確認しません．ライセンスは所有者の判断事項として未設定です．
